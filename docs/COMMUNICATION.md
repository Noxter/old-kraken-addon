# Communication — Мережевий транспорт Old Kraken

Цей документ описує внутрішню роботу транспортного модуля `Communication.lua` та протоколу обміну повідомленнями між клієнтами аддона в гільдії.

---

## 1. Канал та префікс

- **Канал:** `GUILD` (уся комунікація здійснюється виключно всередині гільдії).
- **Префікс повідомлень:** `OLDKRKN`.
- Реєстрація префікса виконується під час `PLAYER_LOGIN` через `C_ChatInfo.RegisterAddonMessagePrefix`.

---

## 2. Формат кадру (`GF2`)

Повідомлення кодуються у форматі з розділювачем `^`:
```text
GF2^KIND^ID^PART^COUNT^HEX
```

- **`GF2`** — версія кадру протоколу.
- **`KIND`** — тип повідомлення (із закритого переліку `VALID_TYPES`).
- **`ID`** — унікальний ідентифікатор передачі (`sessionID-messageSequence`, де `sessionID` генерується на старті сесії).
- **`PART`** — порядковий номер фрагмента (1..COUNT).
- **`COUNT`** — загальна кількість фрагментів (1..32).
- **`HEX`** — шістнадцятковий payload (кожен байт як `%02X`), що зберігає кодування UTF-8 і не конфліктує зі спецсимволами.

---

## 3. Ліміти та параметри черги

| Параметр | Значення | Опис |
|---|---|---|
| `PART_BYTES` | 80 байтів | Максимальний розмір корисного навантаження в одній частині |
| `MAX_PARTS` | 32 | Максимальна кількість частин для одного повідомлення |
| **Максимальний payload** | **2560 байтів** | 80 байтів × 32 частини |
| `MAX_FRAME` | 240 байтів | Максимальний розмір одного рядка повідомлення для чат-системи WoW |
| `MAX_QUEUE` | 4096 | Максимальна місткість черги вихідних повідомлень |
| `ACTION_RESERVE` | 256 | Зарезервовані слоти для високопріоритетних дій (пріоритет 0) |
| `BACKGROUND_LIMIT` | 3584 | Поріг черги для фонових повідомлень (`MAX_QUEUE - ACTION_RESERVE`) |
| `CACHE_TTL` | 120 с | Час життя дедуплікаційного кешу для запобігання обробці дублікатів |

---

## 4. Пріоритети черги та обробка

1. **Пріоритет 0 (Дії):** критичні транзакції та рішення (заявки в групу `JOIN`, `RESPONSE`, скасування `CANCEL`, RSVP на події `CEVRSVP`, дії замовлень `WOREQ`, `WOACT`, `WOPAY`).
2. **Пріоритет 1 (Знімки):** стани та оголошення (`ANNOUNCE`, `UPDATE`, `WORDER`, `CVNEW`, `CVSTATE`).
3. **Пріоритет 2 (Фонові запити):** синхронізація, каталоги, пінг (`QUERY`, `WKQUERY`, `WRQUERY`, `WRIDX` тощо).

**Тікер вибірки з черги (`Pump`):** кожні 0,7 секунди надсилає наступний доступний пакет із найвищим пріоритетом.

**Обробка невдач (Backoff):** при помилках чи тротлінгу API повідомлення залишається в черзі з експоненційним backoff (2, 4, 8... до 60 с) з додаванням джиттера.

---

## 5. Безпека та верифікація відправника

- Аддон не використовує зовнішні сервери для авторизації.
- Кожне повідомлення перевіряє повноваження відправника (`sender-authority`):
  - Зміни в групі приймаються лише від власника оголошення (`sender == owner`).
  - Зміни в календарі подій приймаються лише від автора події.
  - Заявки приймаються лише від самого заявника.
- Для пересланих повідомлень (офлайн-релей) діє обмеження: пряме оновлення від автора завжди перезаписує пересланий стан.

---

## 6. Діагностичні команди

- `/okr comm status` — виводить у чат стан черги, доступність API, лічильники надісланих, отриманих, відкинутих і недійсних пакетів.
- `/okr comm test` — надсилає пінг у канал гільдії; клієнти з аддоном автоматично відповідають ACK, підтверджуючи двосторонній зв'язок.
