# Old Kraken Guild Addon

## Експериментальний транспорт Group Finder

Робоча версія додає протокол `GF2^TYPE^ID^PART^COUNT^HEX`, де HEX кодує байти payload, зокрема UTF-8. Допустимі типи: ANNOUNCE, CANCEL, JOIN, RESPONSE, UPDATE, QUERY, SYNC. Payload обмежено 2560 байтами і 32 частинами. `SendProtocol` повертає успіх лише при додаванні до черги, а не підтвердження доставки. `RegisterHandler` передає обробнику фактичного відправника, ID та декодований payload. Авторизація та перевірка змісту належать майбутньому модулю Group Finder.

Частини складаються незалежно від порядку; незавершені повідомлення та кеш дублікатів обмежено за розміром і часом. `RequestSync` ставить QUERY у чергу, після чого автори поступово передають власні знімки. Підтвердження доставки не реалізовано; дані можуть тимчасово застарівати. Черга зберігає обмеження 50, а на throttle/lockdown робить не більше п'яти спроб. `/okr comm status` показує лічильники; старий TEST/ACK збережений.

Тестовий інтерфейс Group Finder доступний через `/okr group`. Інструкції для локальної перевірки та двох клієнтів, включно з обмеженням імен відправників, наведено в [TESTING.md](TESTING.md). Перевірка в реальному клієнті WoW Forever залишається обов'язковою.

Нові групи учасників гільдії з'являються у сповіщенні на екрані та в чаті зі звуком, якщо він доступний. Клацання по сповіщенню відкриває пошук груп. Кнопка «Сповіщення» у вікні `/okr group` вмикає або вимикає ці повідомлення; вибір зберігається. Старі записи, отримані під час синхронізації, не викликають сповіщення.

Нова заявка також з'являється як сповіщення: натисніть його, щоб відкрити відповідну групу та список заявників. Сповіщення про заявки працюють незалежно від налаштування сповіщень про групи.

Після натискання «Прийняти» аддон намагається запросити заявника в паті через `C_PartyInfo.InviteUnit`. Гра визначає, чи дозволене запрошення; якщо API недоступний або виклик завершився помилкою, запросіть гравця вручну. Сам факт виклику не гарантує доставки запрошення.

Автор оголошення автоматично додає до складу фактичних учасників своєї паті та синхронізує зміни з гільдією, зокрема коли гравця запрошено поза аддоном. Прийняті заявники зберігають зарезервоване місце до приєднання; коли учасник, який був у паті, виходить із неї, місце звільняється. Синхронізація стосується звичайної паті, а не рейду.

У складі біля кожного імені показано «автор», «у паті» або «резерв». Якщо аддон автора ще не визначив склад паті, показано «статус невідомий». Для відображення статусів усім потрібна оновлена версія `alpha`.

Щоб повторно запросити гравця з резерву, автор обирає своє оголошення, вводить повне ім'я гравця в поле «Ім’я учасника» та натискає «Запросити знову». Запрошення можна повторити, поки місце залишається в резерві.

Україномовний аддон для керування гільдійними даними та активностями у WoW Forever.

## Статус

Версія `0.4.0-alpha.2-syncfix`. Для Group Finder обидва гравці повинні оновитися до цієї версії: ідентичність тепер включає ім'я і прізвище персонажа з `UnitName`. Старі короткоіменні заявки очищуються, їх потрібно подати повторно. У Guild Roster є пошук, фільтри, сортування та кольори класів. Зміни потребують тестування безпосередньо в клієнті WoW Forever.

## Цілі MVP

- **Guild Roster** — перегляд і робота з гільдійним ростером.
- **Group Finder** — пошук гравців для груп.
- **Events / Calendar** — планування гільдійних подій.
- **WoW Hub** — додаткове джерело для імпорту або звірки даних ростера.

## Перевірено в WoW Forever 1.60.1 (70938)

У клієнті підтверджено:

- `GetBuildInfo()` повертає interface number `16001`.
- `C_GuildInfo.GuildRoster()`, `GetGuildRosterInfo()` та `GetNumGuildMembers()` доступні.
- `GUILD_ROSTER_UPDATE` спрацьовує після запиту оновлення ростера.
- `C_Calendar` та `C_Calendar.GetEventInfo` доступні.
- `C_ChatInfo.SendAddonMessage` доступна, але `AreOutgoingAddonChatMessagesRestricted()` повертає `true` у перевіреному клієнті.

Наявність функцій не гарантує доступність усіх операцій. Календар і обмін аддон-повідомленнями потребують окремих функціональних тестів.

## Communication diagnostics v0.4.0-alpha.2

- `Communication.lua` додає окремий транспортний шар для guild addon messages.
- Префікс: `OLDKRKN`; канал: `GUILD`.
- Вихідні повідомлення проходять через чергу з повторною спробою при throttle/lockdown.
- Вхідні повідомлення приймаються через `CHAT_MSG_ADDON`.
- `/okr comm status` показує доступність API, реєстрацію префікса та стан обмеження вихідних повідомлень.
- `/okr comm test` надсилає тестове повідомлення; клієнти з аддоном автоматично відповідають ACK. Успішний ACK підтверджує двосторонню доставку між клієнтами.
- Значення `AreOutgoingAddonChatMessagesRestricted()` виводиться як діагностика, але не блокує спробу відправлення: остаточний результат визначається функціональним тестом.
- Потрібно перевірити на двох персонажах/клієнтах у гільдії. До цього спільна синхронізація не вважається підтвердженою.

## Guild Roster v0.4.0-alpha.2

- Пошук за ім'ям персонажа.
- Перемикання фільтра статусу: усі / онлайн / офлайн.

- Сортування за замовчуванням: рівень за зростанням усередині групи онлайн/офлайн.
- Імена та назви класів використовують кольори класів WoW, якщо вони доступні в клієнті.
- Лічильник показує повний склад, кількість онлайн і кількість записів після фільтрації.
- Пошук, фільтри й сортування зберігаються через SavedVariables.

## Джерела даних

- Ігровий гільдійний ростер є основним джерелом актуального складу, рівнів і рангів.
- WoW Hub розглядається як допоміжне джерело. Спосіб отримання та формат імпорту ще потрібно дослідити.

## Архітектура та обмеження

- Самостійний аддон на Lua/XML.
- Початковий етап — без власного backend-сервера.
- Для локальних даних використовується механізм WoW SavedVariables.
- Можливість обміну подіями та даними між клієнтами через канали WoW Forever потрібно окремо перевірити.
- Зовнішні HTTP-запити з аддону не вважаються доступними без підтвердження API клієнта.

### Ініціалізація та локальні дані

- `Database.lua` — єдине місце ініціалізації `OldKrakenDB`, значень за замовчуванням і версії схеми `schemaVersion`.
- `Core.lua` — життєвий цикл аддона та внутрішні події `OldKraken:On()` / `OldKraken:Fire()`.
- `Communication.lua` — діагностичний транспорт обміну addon messages у каналі `GUILD`.
- `GuildRoster.lua` — інтерфейс і робота з ігровим API ростера; налаштування читаються з `OldKraken.DB.settings.roster`.
- Існуючі таблиці `settings`, `roster` та `events` зберігаються під час ініціалізації. Нові поля додаються без очищення наявних даних.
- Поточна схема БД — `2`. Поле `version` залишається версією аддона, а `schemaVersion` використовується для міграцій структури даних.

## Використання

- `/okr` або `/oldkraken` — відкрити вікно ростера.
- Кнопка **Оновити** — запросити оновлення ростера.
- Поле пошуку — фільтрувати за ім'ям.
- Кнопка **Статус** — перемикати усі / онлайн / офлайн.
- Випадаючий список **Клас** — вибрати конкретний клас або «Усі класи».
- Клік по заголовках **Ім'я**, **Ранг**, **Рів.**, **Клас**, **Локація** — змінювати сортування та напрямок.
- `/okr refresh` — запросити оновлення без відкриття вікна.
- `/okr comm status` — перевірити стан транспорту.
- `/okr comm test` — надіслати тестове повідомлення членам гільдії.
